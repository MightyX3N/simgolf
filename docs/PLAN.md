# Project plan

Snapshot of the project plan (Nov 5, 2026). UI previews: https://claude.ai/artifact/UMVxneTwoTRLVCML8gx4J6

## Overview

A Garry's Mod gamemode that rebuilds Sid Meier's SimGolf (2002) in Lua, ported from [OpenSGolf](https://github.com/crspytopgn/opensgolf), written so it can later ship as a standalone LÖVE game.

- **Source:** OpenSGolf, a Rust reimplementation (v0.6.10) with rules and numbers rebuilt from the original game. About 40k lines of game logic in `sg-core` and 68k lines of renderer, UI and tools. The logic is translated to Lua module by module; nothing else is carried over as code.
- **Licence:** OpenSGolf is GPL-2.0-or-later, so this port is GPL too, with source published on GitHub.
- **Goals:** plays like SimGolf by default; runs without the original game files; moddable with asset packs and gameplay addons; modern, clean UI; same code later runs as a standalone LÖVE game.
- **Not included:** Bink intro videos, AI upscaling, OpenSGolf's own updater and record readers.

## Architecture

All game code lives in a shared `core/` that never touches GMod or LÖVE directly; thin platform layers do the drawing, input, networking, files and sound.

- **`core/`** (pure Lua, LuaJIT-compatible): simulation, rule tables, save format, pack loader, addon API, event bus, UI widget library.
- **`platform/gmod/`**: `surface`/`draw`, input, `net` messages, `file`, `sound`, and a bridge that forwards core events to `hook.Run`.
- **`platform/love/`**: `love.graphics`, input, lua-enet, `love.filesystem` + `io`, `love.audio`.
- Core talks only to a `Platform` interface: `Platform.drawImage()`, `Platform.send()`, `Platform.readFile()` and so on.

```
        Asset packs and gameplay addons (same folder format on both)
                                 |
                     core/  (shared Lua)
   simulation · rule tables · saves · pack loader · addon API · event bus · UI widgets
                 |                                   |
          platform/gmod/                       platform/love/
 surface/draw · input · net · file · sound   love.graphics · input · lua-enet · io
   forwards core events to hook.Run          launcher · GitHub updater · playit.gg
                 |                                   |
   Garry's Mod gamemode (Workshop)       Standalone LÖVE game (Windows, Linux)
```

Rules that keep the LÖVE port cheap:

1. Render the course in 2D isometric in a fullscreen panel (like Slither), not in the 3D world.
2. Build the UI from our own widgets, never Derma.
3. The server runs the simulation; clients only render and send actions.
4. The UI only reads game state and sends actions (build, hire, set price); no game logic in UI code.
5. Gameplay hooks go through the core's event bus (`Game.Hook.Add`), so addons work on both platforms.

## Asset packs

Every set of graphics and sounds is a pack in one shared format; the gamemode never cares where a pack came from.

**Pack format** (a normal GMod addon folder, also read as-is by LÖVE):

```
<pack>/
  addon.json
  materials/<game>/<pack>/...   PNG sprite sheets
  sound/<game>/<pack>/...       WAV/OGG
  lua/<game>/packs/<pack>.lua   manifest: id, name, version, frame sizes, anchors, footprints
```

| Pack | Where it comes from | Distribution |
| --- | --- | --- |
| Free (default) | OpenSGolf's opensgolf-free set, exported once with `sgtool freeset` (GPL-2.0-or-later) | Ships with the gamemode on the Workshop |
| Original | Generated by the converter from the player's own SimGolf copy | Local or server FastDL only, never the Workshop |
| Community | Made by players, any subset of files | Workshop |

**Fallback is per file:** if the active pack lacks a sprite or sound, that file comes from the free set. Partial packs are valid. Packs must keep the free set's sizes and anchors, which match the original's, so gameplay never changes.

**Admin switching:** the admin picks the active pack in the admin menu; the server stores it in a ConVar and broadcasts it, and clients switch live. The server sends every installed pack on join (`resource.AddWorkshop` / `resource.AddFile`), since GMod only downloads on join. The menu lists only packs the server has.

**Converter (LÖVE app):** drag in the SimGolf folder and the GMod folder, click Convert, get `garrysmod/addons/<game>_original/`.

- Ports from OpenSGolf: `flc.rs` (FLC animations), `assets.rs` (PCX/TGA/BMP), `gsm.rs` + parts of `sounds.rs`/`wav.rs` (sounds), `formats.rs`/`sprites.rs` (sheet layouts). About 2–3k lines.
- PNG via `ImageData:encode("png")`, WAV written by hand, files written with `io` to absolute paths.
- Optional later: CD/ISO/zip reading from `unpack.rs`/`zip.rs`; plain zips via `love.filesystem.mount`.
- Browse buttons: Windows folder dialog via FFI, `zenity` on Linux; drag and drop always works.

**Legal:** the gamemode only ships the converter and the free set. A server sending the converted original pack to players is redistributing EA's files (a grey area, like CS:S content); the converter warns not to upload it to the Workshop. Game rules always come from built-in tables, never from players' files.

## Gameplay addons

Gameplay addons change rules and add content; they are separate from asset packs, but may include their own sprites registered through the pack system.

| Level | What it does | Example |
| --- | --- | --- |
| Data | Modifies the built-in rule tables after load | `Game.Data.Objects.bench.price = 50` |
| Content | Registers new buildings, decorations, staff, golfer types, events, scenarios, courses | `Game.RegisterObject("fountain_big", {...})` |
| Logic | Hooks key moments to change outcomes or add mechanics | `Game.Hook.Add("ShotResult", ...)` |

Hook points to expose: golfer picks a shot, shot result, mood change, money tick, golfer leaves, tournament end, day/month/year change.

- **Server-only:** the simulation runs on the server, so addons are installed there; their UI Lua downloads to clients automatically.
- **Saves:** content is stored by string ID; a save with unknown IDs loads with them skipped or replaced, plus a warning.
- **Load order:** addons have a priority; a log entry when two addons change the same value.
- **Vanilla mode:** a server setting that ignores all gameplay addons, so original SimGolf rules are one click away.
- **API version:** every addon declares `apiVersion` in its manifest; mismatches are refused or warned about.

## UI

A modern, clean UI replaces SimGolf's original panels, following the UI previews canvas.

**Look:** dark see-through panels over the course, rounded corners, one green accent (#2f9e5b), amber for money (#f5c451), Inter for text and Space Grotesk for headings, outline icons.

| Screen | Contents |
| --- | --- |
| In-game HUD | Club/date card, speed controls, cash/fun/members/rating chips, left tool rail, build drawer with tabs and priced tiles, brush size, undo/redo, cost tooltip, notifications, minimap |
| Golfer selected | Side panel: membership, hole/stroke/score, mood, needs, recent thoughts, follow camera; shot preview and speech bubble in the world |
| Hole stats | Hole list, yards/par/stroke average/fairways hit, design scores (fun, length, accuracy, imagination), strokes-taken chart, golfer comments |
| Reports | Tabs for finances, members, course rating, tournaments, player comments; 12-month chart, monthly breakdown, green fee control |
| Admin | Asset pack switcher with fallback info; gameplay addon toggles; vanilla mode |
| Main menu / lobby | Continue, new, load, sandbox, settings; players on the server with roles; property chooser |

A classic SimGolf-style UI can be added later as an option, since UI is only a layer over game state. Addons can add their own panels through hooks.

## Multiplayer

The server owns the simulation on both platforms; clients render and send actions, so only the transport differs.

- **GMod:** normal Source servers and `net` messages. Players get roles (owner, builder, visitor) controlling who can build and spend.
- **Performance:** golfer pathfinding and mood updates run on a timer in batches, not every tick.
- **LÖVE:** lua-enet (UDP, bundled with LÖVE) with the same sync logic.
- **Hosting without port forwarding (LÖVE):** playit.gg. Its free tier still covers UDP services, and the agent is open source.
  1. Host clicks "Host online"; the game starts the playit agent (Windows or Linux binary) in the background.
  2. First run: the agent's claim URL opens in the browser to link a free playit account; the secret key is then saved so later starts need no login.
  3. A UDP tunnel points at the local enet port; the game shows the `*.ply.gg:port` address with a copy button.
- **Fallback:** direct IP and port join, for port-forwarding or Tailscale/ZeroTier users. Some free playit IPs are on blocklists.

## Standalone LÖVE game and updates

The standalone game is the same `core/` plus `platform/love/`, a launcher and an updater; it runs on Windows and Linux as a fused exe or `.love` file.

- **GitHub updates (main source):** check the Releases API, download the release zip, verify its SHA-256 and ed25519 signature (as OpenSGolf does), unpack into the save folder. LÖVE loads Lua from the save folder, so updates need no new exe. LÖVE 12 has HTTPS built in; LÖVE 11 needs luasec or the system `curl`.
- **Workshop (optional extra):** LÖVE has no Steam support, and GMod's app ID can't be used by our app. steamcmd `workshop_download_item 4000 <id>` can work but is unreliable without a login. `.gma` files are simple to unpack.
- **Packs and addons:** read from the same folder layout in the save directory; the asset converter can be built into the standalone game.
- **Compatibility:** core releases and every pack/addon carry an `apiVersion`; mismatches are refused or warned about.

## Repo layout

One repo holds everything; a build script assembles the GMod gamemode and the LÖVE game from the shared source, because GMod only loads Lua from inside the gamemode folder.

```
core/                 shared game code (simulation, data tables, saves, packs, addon API, UI widgets)
platform/gmod/        GMod layer
platform/love/        LÖVE layer
gmod/                 gamemode entry files (init.lua, cl_init.lua, shared.lua, <name>.txt)
love/                 main.lua, conf.lua, launcher, updater
packs/free/           free asset pack exported from OpenSGolf
tools/converter/      LÖVE asset converter app
tools/build.py        builds dist/gmod/<name>/ and dist/love/ (Python 3, Windows + Linux)
site/                 project website (GitHub Pages)
docs/                 plans and notes (never copied into the GMod build)
LICENSE               GPL-2.0-or-later
```

The build copies `core/` + `platform/gmod/` into `dist/gmod/<name>/gamemode/` and skips `.md` files, which the Workshop rejects.

## Roadmap

Each phase ends with something playable or usable; the LÖVE work comes last, but the rules in Architecture apply from day one.

**Phase 1 – Foundation**

- [x] Repo, licence, build script, `Platform` interface
- [ ] Export the free set with `sgtool freeset` and `sgtool dump-data`; define the pack manifest
- [ ] 2D isometric renderer in GMod: terrain, camera pan/zoom, sprites from the active pack

**Phase 2 – Building a course**

- [ ] Port land generation, terrain painting, elevation, hole building and par
- [ ] Buildings, amenities, decorations; money and costs
- [ ] Build drawer, tool rail and top bar from the UI previews

**Phase 3 – Golfers**

- [ ] Port golfer AI: arriving, walking, shots and ball flight, needs, moods, thoughts, leaving
- [ ] Staff, green fees, membership, daily economy
- [ ] Golfer panel, hole stats, reports

**Phase 4 – Multiplayer and modding**

- [ ] Server-authoritative sync, player roles
- [ ] Pack switching with per-file fallback; admin menu
- [ ] Gameplay addon API: data, content, hooks, vanilla mode, `apiVersion`
- [ ] Saves with string IDs

**Phase 5 – Full game**

- [ ] Properties and themes, tournaments, pro golfer, end-of-year, weather, wildlife, stories
- [ ] Workshop release with the free set

**Phase 6 – Converter**

- [ ] LÖVE app: PCX/TGA/BMP, FLC, sound decoding; writes the original pack addon

**Phase 7 – Standalone LÖVE game**

- [ ] `platform/love/`, launcher, enet multiplayer, playit.gg hosting
- [ ] GitHub updater with signatures; optional Workshop download
